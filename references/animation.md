# 做成动画

本文件是各画风共用的动图/动画规格，需要输出动图时再读取。各画风自己的动图注意事项在 `styles/<slug>.md` 的「毛病清单」里。

- 各画风都有 `stage(name)` 和 `save(path, stages_dir)`，按阶段依次淡入叠化，就是「一幅画被逐步画出来」。README 里的动图就是这样做的。
- 动图规格（多数现有动图和后来新增的都一致）：720×405；每个阶段停 900 毫秒，再用 5 帧（每帧 90 毫秒）叠化到下一阶段，最后一帧停 2600 毫秒，无限循环。后来新增的动图所有帧共用一张 256 色调色板，文件小、不闪烁。
- 调色板别只取最后一帧：满屏单色（黑板的墨绿、赛博朋克的夜色）会吃掉色位，彩色部分被量化成灰。黑板按加权像素样本做中值切分（彩色像素 ×5、亮色 ×2）；赛博朋克从全部关键帧的拼图取 255 色，留 1 个透明色标记「和上一帧相同」的像素，并去掉 Pillow 每帧重复写入的局部调色板（3.8 MB → 1.8 MB）。
- 调色板的另外几条经验（新增的几种里反复出现）：
  - 小面积的点睛色（报刊拼贴的芥末黄纸片、单线画的琥珀色窗、柔光 3D 的黄球）会被量化成土黄、米黄或平色片：取调色板样本时饱和像素 ×5 左右，限定色板的画风可以把色板色强制放进调色板。
  - 大片渐变（弥散玻璃的背景、单线画的深蓝底、Synthwave 的天空）出现一圈圈色带：量化前叠一张固定的 4×4 Bayer 抖动，每帧同一张，「和上一帧相同」的透明差分照样有效。
  - 标记「和上一帧相同」的透明占位色不要用黑色：最暗的阴影像素会被当成透明，自检时大批帧对不上，改用纯品红这类画面里没有的颜色。
  - 最后一个 `stage()` 和成品完全相同时，Pillow 会把相同的帧合并，按帧数自检会报 EOFError：`save()` 前不要紧挨着再调一次 `stage()`。
  - 卡通手绘的抖线动图只抖墨线，铅笔稿和颜色不动，否则每次叠化都整片重编码，体积翻倍。
- 后来新增的十六种（岩画到刺绣徽章）动图又反复用到几条通用做法；改版的动图脚本放在各画风自己的工作目录（如 `claude_drawing/mosaic_work/`），没有进仓库：
  - 加权调色板：取样时饱和像素 ×5 左右、亮色 ×2；红、金、橄榄绿这类面积小的点睛色加权也抢不到颜色时，单独给它们留调色板位（先中值切分出约 240 色，再从这类像素里单独切 6–14 色补上；饱和色多的可按色相区等量抽样，单独分几十色）。
  - 大片渐变、深色上的反光出色带：量化前每帧叠同一张固定的 4×4 Bayer 抖动（约 ±2.4 级）。
  - 满屏网点或硬边像素（漫画网点、低多边形）缩到 720 宽时用 BOX 不用 LANCZOS，否则网点成摩尔纹、硬边出振铃，体积也更大。
  - 满屏细纹理（灰泥、石子、玻璃）每次叠化都会改掉大半像素：叠化帧里和屏上已显示颜色只差一点（约 10/255）的像素沿用上一帧、记成透明，自检按实际显示的帧逐帧比对；墓室壁画、马赛克、彩色玻璃花窗都是靠这一条（再加各自的小改动，见第三节）把动图从 3 MB 多压到 2 MB 以下。
- 这一批十五种（蓝图工程图到绘本角色动画）又多了几条：
  - 满屏几乎一种色调（X 光片的蓝胶片）时，补几个色位不够：按「主色调像素 / 其余彩色像素」两段分别中值切分（186 + 69 色）；OSD 里必须精确的纯白、纯黑、REC 红这类颜色直接强制占色位（热成像、VHS 家庭录像），否则白字被量化成淡黄。
  - 大块色层整片交接的叠化（扁平矢量的夜蓝 → 橙 → 沙）：调色板样本里加上 1/3、2/3 两张叠化帧，Bayer 只叠在两张关键帧不同的地方（整帧都叠更大；Floyd–Steinberg 更大，还会抖出透明占位色）。只有黑白两值的画风（1-bit 早期画图软件）缩小用 BOX、配固定灰阶调色板，不做中值切分。
- 描图纸叠层的动图（脚本在 `claude_drawing/overlay_work/make_gif_overlay.py`）：阶段是 关灯 → 灯变暖 → 开灯 → 底图 → 每张叠片「抬起、偏着」→「放下」→ 胶片图例卡 → 贴胶带。一张纸落下，会让一大片带纹理的区域整体变几级、线条由糊变清，逐帧精确差分要 3–5 MB。做法：目标和屏上已显示颜色的差值拆成平滑分量（模糊 2 px）和细节残差，平滑分量超过阈值（叠化帧 12 级、关键帧 3 级）或单点超过阈值（30 / 16 级）才重发，只有单点超阈值的孤立像素（纸纹在阈值上下翻动）不发；开灯那几帧逐像素精确发送，其中的叠化帧不加抖动（加了每帧每个像素都变）；最后一帧收紧阈值追平。73 帧约 1.9 MB，按解码结果逐帧自检。
- 粉彩界面的动图（脚本在 `claude_drawing/pastelui_work/make_gif_pastelui.py`）：阶段是 圆形擦除铺开底色 → 窗口弹出 → 胶囊、标题、色条、左栏、正文逐行写出 → 面板弹出 → 徽章依次打勾 / 打叉（中间放大镜从第三行飞到天气预报上）→ 三个小图标探头。会动的东西不用叠化：范例里 `move()` 给每样东西几个缓动 / 回弹的中间姿态，存成 `mv_*` 阶段，动图里每个 50 毫秒硬切，就是真运动（写字是 reveal 从 0 到 1，徽章是绕自己中心从 0.3 倍回弹到 1）；其余阶段用 70 毫秒的帧叠化。调色板先强制放进整套界面色，再按加权样本中值切分；固定 4×4 Bayer，没变的像素记成品红透明。107 帧、15.6 秒、约 0.35 MB，按解码结果逐帧自检。
- 阅卷批改的动图（脚本在 `claude_drawing/grading_work/make_gif_grading.py`）：阶段是 桌面 → 答题卡抬着淡入、两帧落下 → 标准答案卡和纸条同样落下 → 夹上长尾夹 → 五行作答逐字出现 → 两个章各「落下两帧 → 压下停 360 毫秒 → 抬起 → 拿走」→ 红笔从右下角进来，给三道计算打勾，画波浪线、圈、引线、批注、叉，划答句，在标准答案卡上打勾打叉，写分数再圈起来，每一笔之间抬笔移过去 → 笔放回得分格旁。阶段名里带时间：带 `~` 的是运动帧（硬切、不叠化），`@毫秒` 是停留时间，其余是关键阶段（停 900 毫秒，相邻两个关键阶段之间 5 帧叠化），所以章和笔是真的在动。重发规则沿用描图纸叠层的平滑分量 / 细节残差阈值；帧一张张算、不全留在内存里；调色板 180 色中值切分（饱和像素 ×5、亮色 ×2）+ 75 色只从饱和像素里切（红笔、朱红印、深蓝页眉、木章），固定 4×4 Bayer。133 帧、21.4 秒、约 1.17 MB，按解码结果逐帧自检，末帧误差和单纯调色板量化相同。
- 皮影戏的动图（脚本在 `claude_drawing/shadowpuppet_work/make_gif_shadowpuppet.py`）：阶段是 黑场 → 灯点着、光晕一圈圈铺开、闪动 → 横楣带着灯笼从上面落下，灯笼晃着亮起来 → 底带和球门从下面升上来，边升边贴紧幕布（由虚变实）→ 四个人从两边侧幕滑进来，离幕远时又虚又是双影，边走边贴上幕布 → 站定 → 同伴挑球传过去 → 球头收腿、起脚，球画一道弧穿过风流眼，青方一个跳起扑空、一个指着球，同伴摆出亮相 → 全体带一点过冲定住 → 两块小牌顺着线落下 → 灯暗一下 → 成品。全部是真运动（`~` 运动帧），一个叠化都没有；阶段名的约定和阅卷批改一样（`~` 运动帧、`@毫秒` 停留）。重发规则同阅卷批改；调色板 150 色中值切分（成品取样 ×8、饱和像素 ×5、亮色 ×2）+ 105 色只从最后几帧的饱和色和冷色里切，再做 6 轮 k-means 收短误差尾巴；固定 4×4 Bayer。61 帧、10.8 秒、约 1.75 MB，按解码结果逐帧自检，末帧误差（p99 16）和单纯调色板量化相同。点灯那几帧和结尾灯暗一下要整帧重发，是最贵的几帧（各 75–130 KB）。
- 钢笔淡彩的动图（脚本在 `claude_drawing/penwash_work/make_gif_penwash.py`）：阶段是 空桌面 → 四张白卡放下 → 第 1、2 张上墨线 → 第 3、4 张上墨线 → 第一遍淡彩 → 第二遍（鼻子、鞋、细部）→ 背景色块 → 白色水粉高光 → 放下针管笔和水笔，都是 900 毫秒 + 5 帧叠化。橡木桌本身就是饱和色，「饱和像素 ×5」会把色位都给木头，淡蓝 / 灰绿背景块被量化成灰青和米色：调色板改成 56 色只从空桌面切、198 色只从和空桌面不同的像素（卡片、墨线、颜料、笔）切（饱和 ×3、末帧 ×3），固定 4×4 Bayer，和屏上已显示颜色差不到 7 级（叠化帧）/ 4 级（关键帧）的像素沿用上一帧，末帧精确发送。49 帧、13.4 秒、约 0.77 MB，按解码结果逐帧自检，末帧 p99 误差 23。

- 暮色微缩绘本的动图（脚本在 `claude_drawing/twilight_work/make_gif_twilight.py`）：
  - 画幅：范例是 2000×1100（20:11），左右各裁 22 px（只有天空和花坡，宽度的 2.2%）成 16:9，再缩到 720×405。
  - 阶段：黄昏天空（渐变、云带、光线、淡日、飞鸟、蒲公英种子）→ 夜从右边进来（夜空渐变、银河、星星、弯月、流星）→ 山（远山、拼布条纹山丘、小圆树、小屋）→ 野花坡 → 小斗篷角色、萤火虫罐和风筝 → 萤火虫 → 放大图和两行手写字（成品）。颗粒、光晕、暗角和撕纸边在 render 里加，每个阶段都有。每段 900 毫秒 + 5 帧叠化。
  - 两大片渐变（黄昏天空、昼夜交界）最容易出色带。照前面的做法（各段中值切分 + 4×4 Bayer + Pillow 按调色板量化）出的第一版，交界处是一圈圈紫 / 粉 / 黄的等高线；交界带的像素到最近调色板色的距离 p90 有 13.6 级。改法：
    - 天空一起切 136 色：一份样本里放第一帧（只有黄昏天空）、夜改动的像素（交界带，即亮度 > 0.13 的部分 ×8，比纯黑重得多）和天空 → 夜那次叠化的中间帧（×0.5）；黄昏和夜分开切时，两份调色板在交界处接不上，留下一块锯齿边的紫斑。其余 104 色从后面的阶段切（末帧 ×3、饱和 ×3），再留 14 色给末帧误差最大（> 14 级）的像素。每份都是中值切分后再做 10 步 k-means。
    - 不用 Pillow 的 quantize(palette=…)，numpy 逐像素找精确最近色（同一张调色板，天空的 p90 误差 8 → 6）。
    - 8×8 Bayer：别处 ±2.4 级，交界带（夜改动过、又不是近黑的天空）加到 ±6.4 级，调色板再密也还差几级的地方靠它抹平。
  - 和屏上已显示颜色差不到 7 级（叠化帧）或 4 级（关键帧）的像素沿用上一帧，末帧精确发送。
  - 结果：37 帧、10.7 秒、约 0.87 MB，按解码结果逐帧自检，末帧 p99 误差 16；交界带模糊 1.5 px 后和原图比 p99 7 级。
